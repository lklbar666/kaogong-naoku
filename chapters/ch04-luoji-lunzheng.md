# 第四章：逻辑判断·论证

## 核心思想

论证题是逻辑判断中题量最大的部分。核心是分清论点和论据，理解加强和削弱的逻辑。

## 论证基础

### 论证结构
- **论点**：结论、观点（通常在"因此/所以/由此可见"后）
- **论据**：支持论点的事实、数据、理由
- **论证**：从论据到论点的推理过程

### 找论点的方法
1. 看关键词：因此、所以、认为、由此可见、据此认为
2. 首尾句原则
3. 结合提问方式（问"反对者观点"就找反对者说的）

## 一、加强论证

### 加强方式（力度排序）

| 方式 | 说明 | 力度 |
|---|---|---|
| 搭桥 | 建立论据和论点之间的联系 | 最强 |
| 补充论据 | 解释原因、举例子、给数据 | 中等 |
| 必要条件 | 论点成立必须满足的条件 | 强 |
| 重复论点 | 肯定论点 | 弱 |

### 1. 搭桥（前提假设）
- 适用：论据和论点话题不一致
- 方法：在论据和论点之间建立联系
- 特征：问"前提/假设/必要条件"
- 验证：否定代入法，搭桥不成立则论点不成立

### 2. 补充论据
- **解释原因**：说明为什么论点成立
- **举例子**：提供具体案例支持
- **解释因果机制**：说明A如何导致B
- 力度：解释原因>举例子

### 3. 只有论点无论据
- 优先补充论据
- 解释原因或举例子

## 二、削弱论证

### 削弱方式（力度排序）

| 方式 | 说明 | 力度 |
|---|---|---|
| 否论点 | 直接否定论点 | 最强 |
| 因果倒置 | 把因果关系倒过来 | 最强 |
| 拆桥 | 切断论据和论点的联系 | 强 |
| 他因削弱 | 提供其他原因 | 中等 |
| 否论据 | 否定论据的真实性 | 弱 |
| 举反例 | 个例反驳 | 弱 |

### 1. 因果倒置
- 论点：A导致B
- 削弱：B导致A
- 通常是最强削弱
- 特征：论点有因果关系（导致、使得、引起）

### 2. 拆桥
- 切断论据和论点之间的联系
- 适用：论据和论点话题不完全一致
- 方法：指出论据推不出论点

### 3. 他因削弱
- 论点：A导致B
- 削弱：C也能导致B（另有他因）
- 注意：需要在同一时间点存在

### 4. 否论点
- 直接说论点不对
- 力度最强但通常不直接出现
- 预测答案：找论点的反面

### 5. 举例削弱
- "有的/某些"式个例
- 力度较弱
- 但在因果倒置等不存在时可选

## 三、因果论证特殊方法

### 求异论证
- 两组对比，有A有B，无A无B → A导致B
- 加强：排除他因
- 削弱：另有他因、因果倒置

### 求同论证
- 多个场景都有A且都有B → A导致B
- 削弱：找共同的其他因素

### 共变论证
- A变化B也变化 → A导致B
- 削弱：因果倒置、B的变化有其他原因

## 四、典型论证模型

### 1. 枚举归纳
- 从部分推整体
- 加强：样本有代表性、数量足够
- 削弱：样本特殊、数量不足

### 2. 类比论证
- A和B相似，A有某属性，B也有
- 削弱：本质不同
- 加强：本质相似

### 3. 数据论证
- 用数据证明论点
- 注意：绝对数vs相对数、分子分母关系

### 4. 形式论证
- 论点可以翻译为逻辑表达式
- 按翻译推理规则处理

## 论证题解题步骤

1. **看提问**：加强还是削弱，选是还是选非
2. **找论点论据**：明确论证结构
3. **预判答案**：根据论证特征预判
4. **辨析选项**：
   - 话题不一致→无关
   - 力度不足→次选
   - 方向错误→排除
5. **比较选项**：选力度最强的

## 常见错误选项

| 类型 | 特征 |
|---|---|
| 无关选项 | 话题不一致、主体不同 |
| 不明确选项 | "可能/也许"、"有待研究" |
| 对策选项 | "应该怎么做"而非论证 |
| 诉诸权威 | "专家说"但无实质内容 |
| 诉诸无知 | "没发现"不等于不存在 |
| 类比不当 | 用不相关的类比 |

## 母题抽象

🧩 **因果倒置母题**：当论点是"A导致B"且论据是相关性数据时，优先找"B导致A"的选项，这是最强削弱。

🧩 **搭桥母题**：当论据和论点讨论的话题之间有明显跳跃，且问"前提假设"时，找建立两者联系的选项。

🧩 **他因削弱母题**：当论点是因果关系时，找同一时间存在的其他原因，可削弱但力度不如因果倒置。

## 关键 takeaway

1. 先分清论点和论据
2. 加强优先搭桥，削弱优先否论点/因果倒置
3. 因果倒置是最强削弱
4. 话题不一致的选项直接排除
5. 力度比较：直接>间接，必然>可能
